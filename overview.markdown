## 사업 목적

채용 과정에서 발생하는 반복 업무를 자동화하고, 흩어진 지원자 정보를 하나의 플랫폼으로 통합하여 채용 담당자의 업무 효율성을 높인다.

채용담당자가 공고를 올리고, 지원자가 외부 링크로 지원서·이력서를 제출하면, 담당자·면접관이 칸반 보드에서 단계별로 심사·평가하고, 단계 변경 시 지원자에게 메일이 자동 발송된다. 흩어져 있던 채용 과정(접수 → 서류 검토 → 면접 → 합불 통보)을 하나의 시스템으로 묶고, 모든 단계 이동에 이력과 평가 기록이 남게 한다.

그 위에 **도구 호출 AI 에이전트(아르)** 를 얹는다 — "백엔드 공고에서 3년차 이상 찾아서 상위 2명 면접으로 올려줘" 같은 자연어 한 문장이 검색 → 조회 → 단계 변경으로 분해되어 순차 실행되고, 쓰기 작업은 반드시 사람의 확인을 거친다.

---

## 시스템 개요 — 한 장면으로

1. 채용담당자가 공고를 등록하면 **공개 지원 링크**가 생성된다. 지원자는 로그인 없이 지원서를 작성하고, 이력서는 presigned URL로 브라우저에서 S3에 직접 업로드된다(파일이 API 서버를 거치지 않는다).
2. 접수 시 1회, **지원자 AI 요약**이 자소서·프로필을 공고 요건과 대조해 요지·적합·우려를 생성해 저장한다.
3. 담당자·면접관은 **칸반 보드**에서 카드를 드래그해 단계를 옮긴다. 모든 이동은 누가·언제·왜까지 이력으로 남고, DB 커밋이 성공한 변경만 메일 큐(SQS)로 나가 워커가 SES로 발송·재시도한다.
4. 면접 일정은 에이전트가 면접관 가용 시간을 파악해 후보를 제안하고, 지원자는 안내 메일의 링크로 24시간 접속해 일정을 선택·확인한다.

## 채용 단계 모델 — 단계는 다섯, 규칙은 셋

`지원 접수(applied) → 서류 검토(screening) → 면접(interview) → 최종 합격(accepted) / 불합격(rejected)`

| 규칙 | 내용 |
|------|------|
| 전진은 순서대로만 | 단계를 건너뛰는 전진 이동은 허용하지 않는다 |
| 뒤로 이동은 담당자 권한 | 역방향 이동은 채용담당자만 수행할 수 있다 |
| 불합격은 어느 단계에서든 | 단, 사유(reason) 기록이 필수다 |

단계는 DB enum이 아니라 코드 상수 + 체크 제약으로 관리하고, 전환 규칙은 DB 트리거가 아니라 서비스 레이어가 강제한다 — 값이 바뀌어도 마이그레이션이 필요 없다. 일괄 단계 변경은 "전부 성공 또는 전부 실패(롤백)"를 보장한다.

## AI 적용 원칙

**버튼으로 되는 일에는 AI를 쓰지 않는다.** 비정형 문서 이해, 자연어 요청의 작업 분해처럼 버튼으로 안 되는 일에만 쓴다.

| 원칙 | 내용 |
|------|------|
| 합불 확정은 사람의 것 (ADR-0003) | AI 산출물은 전부 "제안" 상태로 시작하고 사람의 명시적 액션으로만 확정된다. UI 문법(앰버 점선 = AI 제안 / 잎초록 실선 = 사람 확정)까지 이 원칙을 따른다 |
| 쓰기 확인 강제 | 읽기 도구는 즉시 실행하되, 쓰기 도구(단계 변경·면접관 배정·메일 초안)는 확인 카드로 반환되어 사용자가 승인해야 실행된다 |
| 근거 기반 응답 | 에이전트 응답은 도구 결과만 인용한다(환각 가드). 면접 분석은 STT → RAG → 요약 파이프라인으로, 근거 문서 없이 모델이 단독 판단하지 않는다 |
| 비용·품질 관측 | 프롬프트는 코드로 버전 관리하고, 호출마다 모델명·토큰 사용량을 로깅한다. 대량 더미 데이터에는 AI 호출을 금지하는 비용 가드를 둔다 |
| 영구 제외 | 합불 자동 확정, 표정 분석(의사결정에 사용 불가), speech-to-speech(음성은 STT → 텍스트 에이전트로만) |

## 추진 체계 — 도메인 오너제

한 사람이 도메인 하나를 소유하고, 자기 도메인 로드맵이 자기 작업의 기준이 된다(ADR-0007). 팀장 머지·검수는 매주 금요일.

| 도메인 | 담당 | 범위 |
|--------|------|------|
| 인프라·총괄 | 이재우 (팀장) | 인프라·CI/CD·AWS — 전원의 선행조건 |
| 백엔드 | 이우정 | 코어 API(인증·공고·지원서·평가·검색) |
| 에이전트 | 진수택 | 도구 호출 에이전트·AI 요약·RAG·일정 자동화 |
| 프론트엔드 | 박소연 | React 웹 클라이언트 |
| 앱 | 김민아 | Flutter 모바일 클라이언트 |
